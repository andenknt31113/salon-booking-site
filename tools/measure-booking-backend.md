# 予約の読込遅延を切り分ける

この道具は制作担当者向けです。予約・取消・日時変更・メール送信・管理保存は実行しません。公開画面へは配信しません。

## 通信しない確認

リポジトリのルートでNode.js 22を使います。外部ライブラリ・ビルド・認証情報は不要です。

```sh
node tools/measure-booking-backend.mjs --help
node tools/measure-booking-backend.mjs --dry-run
node --test test/measure-booking-backend.mjs test/read-probe-cli.mjs
```

試験の実CLIも架空のfetchだけを使い、Googleへ通信しません。既定実行はdry-runです。`--run`を指定しない限り読取要求を送りません。

## 許可済みの接続先で一回ずつ測る

`GAS_EXEC_URL`には対象環境の既存GAS受け口を環境変数で渡します。本番の読取を許可された作業でだけ実行してください。URLや取得本文を共有資料へ貼る必要はありません。

読取要求も通常のGAS入口を使うため、共通ロックや、途中停止した日時変更の既存リカバリー処理を通ります。この道具はその処理を停止・迂回しません。未復旧の台帳をそのまま観察する必要がある障害対応では、先に担当者と確認し、計測だけだから台帳へ一切影響しないとは扱わないでください。

```sh
node tools/measure-booking-backend.mjs --run \
  --endpoint "${GAS_EXEC_URL:?対象環境のGAS受け口を指定してください}" \
  --attempts 1 --max-attempts 3
```

送る要求はメニュー、メニューと初期空席、空席単独の3種類に固定しています。逐次実行し、既定は15秒の一回期限、120秒の全体期限、1秒間隔です。各ケース最大4回・全体最大12回を超える引数は通信前に拒否します。転送先はGoogleの結果取得先に限定し、POST本文を転送・再送しません。期限切れでは残りの計測も停止しますが、送信済みのGAS実行を取り消せたとは保証しません。

全要求が有効な応答で完了した場合だけexit 0です。HTTPエラー・不正応答・期限切れを含む場合はexit 1となり、失敗の内訳を残します。失敗時に予約送信や台帳の手修正で試さないでください。

## 結果の読み方

- `roundTripMs`は通信・Googleの転送・応答本文読込を含む往復時間です。
- `serverTimingMs.lockMs`はGASが報告した共通ロック取得待ちです。
- `serverTimingMs.catalogMs`はメニュー・設定等の取得処理です。初期空席付きでは空席取得も含みます。
- `serverTimingMs.totalMs`はGASが報告した要求処理です。応答本文の配信やGAS関数が始まる前の待ちは含みません。空席単独など未報告の値は0ではなく欠落として扱います。
- `first`は各ケースの最初の試行、`later`はその後です。初回／後続や往復／GAS内の差だけからコールドスタート・通信・混雑の時間を断定しません。
- `p95`は少数試行のnearest-rank集計です。一回の値を安定した応答時間や改善率の保証にしません。認証付き管理操作・予約確定・メール配送の速さを測った結果でもありません。

出力は件数・時間・失敗種別・HTTPステータスだけです。取得したURL・本文・顧客情報・未知の計測項目は出力しません。確認したGitの版、GASの配信版、計測日時を非公開の作業記録へ併記し、同条件の比較と異なる条件での観察を区別してください。
