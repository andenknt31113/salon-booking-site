# 公開データの同期

Node.js 22以上で、リポジトリのルートから実行します。

```sh
node tools/publish-menus.mjs --check-site
node tools/publish-menus.mjs --write-site
node tools/publish-menus.mjs --check-local
```

`--check-site`は、設定された予約受け口を読取専用で呼び、メニュー・店舗情報・スタイル写真と公開元の差分を確認します。差分ありは終了コード1で、ファイルを書き換えません。`--write-site`は同じ公開用応答を検査し、公開データと五ページの初期HTMLを一緒にローカルへ書き出します。予約台帳・通知設定・受け口の設定は変更せず、commit・push・デプロイもしません。

写真や設定の取得失敗、欠落・重複した見出し、公開用の印がない応答、不正な写真URLでは更新を止めます。写真を全て非表示にした場合は、正常な空の一覧として同期し、元の写真へ戻しません。顧客・施術メモ・非公開設定・口コミ本文は生成対象に含めません。公開内容を確認してから、通常の配信手順を行ってください。

従来の`--check`・`--write`はメニューだけを取得し、既に静的公開した店舗情報・写真を保持します。`--check-local`・`--write-local`は外部に接続せず、保存済みの公開データと初期HTMLだけを照合・再生成します。

接続先は既存の店舗設定、または`RESERVATION_ENDPOINT`環境変数で指定します。別の受け口を使う場合にのみ、環境変数を指定してください。同期に管理者のpassword・tokenは使いません。

管理画面の「保存」は台帳への保存です。静的公開サイトへ自動反映する処理ではありません。メニューの公開には、下の専用workflowか従来の制作担当者の手順を使います。管理画面からの直接公開や店主へのGitHub権限付与は含めません。公開ページを再び非同期の設定待ちへ戻すものではありません。

公開データを読む九ページのscript URLには、ファイル内容のSHA-256を付けます。内容が変わった場合だけURLを変え、以前のブラウザcacheで新しい初期HTMLを巻き戻さないようにします。五ページの初期表示と、九ページの読込URLを同じ更新・復旧処理へ含めます。生成位置の欠落・重複は更新前に拒否します。

## 保存済みメニューを公開する

GitHub Actionsの「Update saved menus and publish」を開き、`main`を選んで`confirm_publication`を有効にして実行します。制作担当者がリポジトリの既存権限で操作する手順です。既定値は無効で、別branchや確認なしの実行は取得・commitより前に停止します。

書込権限は更新jobだけに限定します。予約側の保存済みメニューを取得し、既に公開した店舗情報・スタイル写真を保持したまま、公開データ一枚と九HTMLの計10ファイルだけを検査・commit・pushします。実台帳・GAS・通知設定・内部資料は更新しません。公開以外の差分、検査後の変更、先に進んだmain、push拒否では停止し、force pushしません。

更新後の版を共通のPages workflowへ渡し、配信直前に予約側のメニューとmainを再確認します。差分がない場合も配信を行うため、前回の配信失敗後に同じ手順を再実行できます。更新jobの成功だけで公開完了とはせず、配信jobの成功と公開ページの内容を確認してください。失敗時は元の成功した公開版を使い、実行記録とmainの差分を確認してから再実行します。
