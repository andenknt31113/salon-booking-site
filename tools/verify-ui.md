# 予約・管理の画面をまとめて検査する

## 実行

Node.js 22と、手元に導入済みのPlaywright・Chromiumを使います。新しいライブラリやブラウザはこの道具からインストールしません。

`.env.example`の`PLAYWRIGHT`に既存runtimeのモジュール名または絶対パス、`CHROMIUM`に既存ブラウザの実行ファイルパスを設定し、値は手元の`.env`へ保存します。`.env`や認証情報をGitへ追加しないでください。通常の`playwright`とそのブラウザが既に利用できる環境では、この2項目の指定は不要です。

```sh
node --env-file=.env tools/verify-ui.mjs
```

環境変数として設定済みの場合は、`node tools/verify-ui.mjs`でも実行できます。追加のCLI引数は受け付けません。

対象は`tools/verify-ui.mjs`の`UI_CHECKS`に登録された全ファイルです。ブラウザを大量に同時起動しないよう、ファイル単位で一つずつ実行します。各試験は自分で空いている一時ポートを使う模擬受け口、または通信を遮断した画面を用意します。事前に固定ポートのサーバーを起動する必要はありません。既存の稼働中サーバーを変更しません。

## 検査する内容

- メニュー・日時・必須入力・同意・最終確認から、架空の予約を一回だけ受け付ける流れ。
- 店舗情報・写真の静的同期後、六つの公開ページで初期表示と実行時の値を揃え、設定の非同期取得や全非表示から古い写真への復帰を起こさないこと。
- 公開データを長期cacheしたChromiumでも、更新した紹介文・写真と全非表示を初期HTMLと同じ版で読むこと。経路の模擬ではなく、cacheを無効化するroutingを使わずCSPで外部通信を遮断します。
- お客様の最新の予約確認・取消の確認と、端末上の古い予約表示を照会結果へ同期すること。
- 読込障害時の予約下書きと、電話受付・メモ・取消の保存結果が不明な場合の確認。
- 管理の初回読込、壊れた応答の拒否、予定更新中の休業日・未保存入力の保護。
- 初回は今日の予定だけを描画し、5,000件の索引・未来・取消・メモを保持したまま、日付移動・全期間表示・手動更新ができること。
- CSVは選んだ日・状態の条件で出力し、全件の出力前に「すべての日・状態に戻す」を選べること。
- お客様と日付の詳細取得、遅い応答の競合、全件CSV・名簿のページ移動。
- 通知・メール配送の状態、公開メニューの読取照合、重なる時間休みの稼働率。
- 日付の前後移動・電話受付の日付、名簿検索の解除、未保存メモの保護とスマートフォンの操作幅。
- 従来版／A案と4画面幅で、Tab移動した休業メモが固定保存バーに隠れず、入力・保存操作が保持されること。
- 従来版／A案で、保存済み・未反映のどちらでも、不完全な保存応答を成功と表示せず、入力を保持し自動再送しないこと。

## 安全性と結果の読み方

`MOCK_ADMIN_PASSWORD`と`MOCK_ADMIN_TOKEN`は本番の値を使わず、毎回新しく生成します。リポジトリ外の読み取り制限付き一時`.env`から渡し、出力では値を伏せ、通常終了・試験失敗とも一時領域を削除します。既存`.env`を書き換えません。強制終了・電源断時の削除は保証しないため、残った`zer01-booking-check-*`を共有・Gitへ追加しないでください。

親の模擬認証値、`GAS_SOURCE`／`ADMIN_SOURCE`など別ソースの指定、`BASE`、Nodeの追加起動指定、画面保存先は流用しません。検査するソースは同じチェックアウトのものです。実行するブラウザはChromiumで固定し、Firefox／WebKitの全互換性を証明する試験ではありません。

試験件数・成功数・失敗数を表示し、実行失敗・試験失敗・結果集計なしでは終了コードを成功にしません。実台帳・本番GAS・Firebaseへログインして試験する道具ではなく、実予約や実メールは送信しません。成功しても、実Googleログイン・本番の往復速度・メール配送・店主の操作確認が完了したとは扱わないでください。

GASの予約・管理境界の単体試験は、別の`node tools/verify-booking.mjs`を使います。GitHubの読取専用CIには実行道具自体の単体試験を登録し、この画面試験27ファイルの自動実行やブラウザの新規導入は追加していません。
