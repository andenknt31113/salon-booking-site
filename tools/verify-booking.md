# 予約・管理保存の安全性を確認する

Node.js 22以上で、リポジトリのルートから実行します。外部ライブラリ、ブラウザ、常設サーバー、Googleのログインは不要です。

```sh
node tools/verify-booking.mjs
```

対象は`BOOKING_CHECKS`にある41ファイルです。現在のGASコード、管理画面の保存応答、模擬台帳の競合、お客様の照会応答を架空のサービスで検査します。実台帳・本番GAS・メール・LINE・カレンダー・クラウド設定へ接続しません。新しいMacやGitの独立展開でも同じコマンドを使えます。

- 予約の最終条件・最新空席の検査と読込の整合性。
- 公開データを読み込む九ページで、初期HTMLと同じ内容hashをURLに含め、更新後にブラウザの旧データを再使用しないこと。同じ内容なら版を変えず、余分なcache破棄をしません。
- 公開用の店舗情報・スタイル写真は、完全な見出しと設定を確認した一回ずつの読取から生成すること。不明な写真一覧や不正な公開メニューを空へ置き換えず、許可外の設定・顧客・口コミを持ち出さないこと。初期HTMLと公開時の値を一緒に更新し、旧メニュー更新でも既に公開した店舗情報を消さないこと。
- 日付と時刻を同じ時点の日本時間で判定し、日付・年・うるう日の切替中も過去の枠を保存・通知しないこと。直前受付・60日先までの範囲・管理の直前変更の例外は変えません。
- 予約確認は全件の番号と対象1行だけを読み、途中の列変更や行の入替えで別の内容を本人の予約として返さないこと。
- 予約確認では台帳の作成・列補完をせず、消えた台帳・不明な見出しを予約なしと取り違えないこと。未対応の操作を新規予約へ送らないこと。
- 来店日不明の実在する予約を空席扱いせず、取消済み予約・空行と区別すること。
- 予約・電話受付の保存確認と同じ受付の再送防止。
- 日時変更の部分保存・反映失敗からの復旧と復旧不能時の拒否。
- 管理の日時変更は、番号・変更先・所要時間・予約内容が一致する応答だけを完了表示へ渡すこと。結果不明・矛盾・応答の欠落では入力と元の予定を保持し、再保存せず手動の読取で確認すること。
- 取消の結果照合と、古い画面から別の予約状態を上書きしないこと。
- 管理権限の境界・旧ログインの拒否、施術メモの保存確認。
- 公開応答と処理ログへサービス例外の認証値・個人情報を出さず、アプリが用意した案内と保存結果不明・復旧・入力検証の状態を保つこと。
- メモの予約番号・保存内容を確認できない応答では成功と表示せず、下書きを残すこと。別画面の競合と同じ内容の再送を区別すること。
- 休業日の入力検証と競合保護、画像登録の認証・ロック。
- 設定保存は対象だけの印を要求した場合に無関係なシートを読み込まず、旧APIの全対象の印も維持すること。保存印が欠けた成功応答や矛盾した結果は保存済みにせず、下書きを保持すること。
- Google本人確認を予約ロックの外で行い、認証・ロック待ちの失敗で台帳を触らず、取得したロックだけを解放すること。
- 前日通知の再実行・途中失敗・送信前の取消確認と、結果不明や壊れた進捗を自動再送しないこと。
- バックアップは新しい控えの番号とその記録を確認してから古い控えを整理し、記録不明・コピー失敗・ロック失敗では本体や古い控えを削除しないこと。実Driveの保管権限・定期実行・別台帳への復元は、この架空試験だけでは確認できません。

対象一覧は`tools/verify-booking.mjs`の`BOOKING_CHECKS`です。実行結果に件数と失敗数を表示し、対象の欠落・実行失敗・試験失敗では終了コードを成功にしません。

試験用の`MOCK_ADMIN_PASSWORD`と`MOCK_ADMIN_TOKEN`は毎回新しく生成し、リポジトリ外の読み取り制限付き一時`.env`から子プロセスへ渡します。通常終了・試験失敗とも一時領域を消し、値は出力しません。親の同名設定・`GAS_SOURCE`指定・Nodeの追加起動指定を流用せず、このチェックアウトのGASを検査します。強制終了・電源断時の一時ファイル削除までは保証しません。残った`zer01-booking-check-*`を共有・Gitへ追加しないでください。

個別の試験を直接実行する場合の環境変数名だけをルートの`.env.example`に記載しています。一括コマンドでは手元の`.env`を作る必要はありません。

この成功は実Googleログイン・実メール受信・店主の操作・本番の速度・HPB切替の確認を代替しません。画面や静的公開ファイルの試験も別です。CIでは同じ一括コマンドを実行し、将来のGAS変更で今回確認した防御を落とさないようにします。

## 受付結果が矛盾する場合

新規予約・日時変更・取消の共通送信処理は、成功と結果不明／確定拒否が混在した応答、真偽値ではない判定、成功にエラー文が付く応答を受付結果不明にします。控えを消したり、日時変更・取消の成功を先取りしたりせず、同じ予約番号で最新状態を確認します。自動再送はしません。

正常な成功・確定拒否・結果不明の区別と既存の追加情報は保持します。接続先が未設定なら送信前に拒否し、新規予約は完了表示に進まず、確認画面と入力を保持します。接続・本文の待ちには既存の上限を使い、中止要求に反応しない通信も待ち続けません。この判定を強める修正で、GASの実処理を速くしたとの意味ではありません。

`test/booking-write-response.mjs`を一括予約検査に、公開画面で控え・日時・取消表示・再読込後の再送抑止を確認する`test/booking-write-response-browser.mjs`を一括画面検査に含めています。架空の受け口だけを使い、実台帳に送信しません。

## Git履歴のない展開で管理の契約を確認する

```sh
node --test test/hermetic-admin-contracts.mjs
```

管理予定表・休業日・選択履歴の78条件を、必要なソースだけの独立コピーで実行します。Git・履歴・元のチェックアウト・ブラウザ・外部サービスを使わず、日本時間とUTCで全条件を確認します。固定契約の欠落・不一致は失敗として扱い、旧版への代用・現実装からの期待値生成・自動更新をしません。

`test/fixtures/admin-contracts.json`は、記載した旧版の架空データの期待結果をSHA-256で固定したものです。予定表の全HTML、管理応答の全フィールド、既存の読込範囲とアクセス回数を確認します。Objectのキー順は比較に影響させず、配列順・値・HTML全文を保ちます。追加済みの電話メニュー能力と、見出しを含める配送読込は、既存の許容差分として記録しています。実顧客・認証情報・本番台帳のsnapshotではありません。

仕様を意図して変える場合は、元の期待と新仕様の差を個別に確認してfixtureを変更してください。試験を通すためだけにハッシュを取り直さないでください。78条件のほかに六条件があり、独立コピーでの実行、fixtureの欠落・不一致、文字のescapeを失う実装、料金をゼロにする実装を検査します。変えるのは破棄する試験用コピーだけです。CIもGit履歴を追加取得せずに実行します。
