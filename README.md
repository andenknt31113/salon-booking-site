# ZER01 barber/lounge 予約サイト

茨城県龍ケ崎市中根台のメンズ専門バーバー **ZER01 barber/lounge** の予約サイトです。
ホットペッパービューティーと同じ操作感（空席カレンダー＋ステップ式の予約）を保ちつつ、
見た目はバーバーラウンジ向けに作っています。

ビルド不要・依存パッケージなし。HTML / CSS / 素の JavaScript のみで動きます。

**公開までの手順は [公開前チェックリスト.md](公開前チェックリスト.md) にまとめています。**
方針の背景と「作らないと決めたもの」は [DECISIONS.md](DECISIONS.md) を参照してください。

## 予約フロー

ホットペッパービューティーと同じ順序です。

```
STEP1 メニュー → STEP2 スタッフ → STEP3 日時 → STEP4 お客様情報 → STEP5 確認 → 完了
```

STEP3 の空席カレンダーは「時間 × 日付」のグリッドで、
選択中メニューの所要時間ぶん連続して空いている枠だけを予約可として表示します。

| 記号 | 意味 |
| --- | --- |
| ◎ | 空きに余裕あり |
| ○ | 予約可 |
| △ | 残りわずか |
| × | 予約不可 |
| - | 休業日 |

画面下部に「電話」「24時間ネット予約」を固定表示しているので、スマホからすぐ予約に進めます。

## 設定を変える

編集するのは基本的に **`assets/js/data.js` の1ファイルだけ**です。

```js
name: 'ZER01',
nameSub: 'barber/lounge',
tel: '080-4498-7036',       // 空にすると電話ボタンを表示しません
address: '茨城県龍ケ崎市中根台1丁目1-1 ロイヤルヤエ 002',

business: {
  openTime: '09:00',        // 営業開始
  closeTime: '22:00',       // 営業終了
  lastOrder: '21:00',       // 最終受付
  slotMinutes: 30,          // 予約枠の刻み
  closedWeekdays: [],       // 固定の定休日（不定休なので空）
  closedDates: [],          // 出張・臨時休業。終日なら '2026-08-20'、
                            // 時間帯だけなら { date:'2026-08-20', start:'14:00', end:'16:00' }
  bookableDays: 60,         // 何日先まで予約を受けるか
  minLeadHours: 2,          // 当日予約の締め切り
  calendarDays: 14          // 空席カレンダーの表示日数
}
```

**出張などで受けられない日は `closedDates` に足してください。**
日付だけなら終日休み、`start` / `end` を入れるとその時間帯だけ止まります。
ふだんは管理ページの「休業日」タブから、コードを触らずに追加できます。

メニューとクーポンは、GAS 設置後は**スプレッドシートで管理できます**（後述）。
`staff` / `styles` / `reviews` / `faq` は data.js を編集してください。

配色を変えたいときは `assets/css/style.css` の先頭にある `--accent` を書き換えてください。

## 予約データの扱い（重要）

GitHub Pages はサーバー処理を持たない静的ホスティングです。そのため2つのモードがあります。

### デモモード（初期状態）

予約はその端末のブラウザ（localStorage）に保存されるだけで、**店舗側には届きません。**
動作確認・社内でのレビュー用です。

### ユースケースと試験

「誰が・どの場面で使うか」を [ユースケース.md](ユースケース.md) にまとめ、
そのまま自動試験にしてあります（19シナリオ／86項目）。

```bash
node test/settings.mjs      # 2か所に書いた設定の食い違い（ブラウザ不要）
node test/mail.mjs          # メールの文面（ブラウザ不要）
node test/backend.mjs       # 受け口におかしな入力を投げる（ブラウザ不要）
node test/mock-gas.mjs      # Apps Script の代わりのテスト用サーバー
node test/usecase.mjs       # 別のターミナルで実行
node test/quality.mjs       # 構造化データ・OGP・操作しやすさ
node test/escape.mjs        # お客様が書いた文字の出方（画面）
node test/slow.mjs          # 通信が遅いときの表示
```

`test/usecase.mjs` `test/escape.mjs` `test/slow.mjs` は `test/mock-gas.mjs` を
立ち上げてから実行してください。試験のはじめに台帳を空に戻すので、
サーバーは立ち上げっぱなしで構いません。

予約・確認・変更・キャンセル・口コミ・休業日・値段変更に加えて、
**同時に同じ枠を押された場合**、**受付期限を過ぎた場合**、
**店舗に届かなかった場合**も確認しています。

`test/quality.mjs` は検索結果への出方（構造化データ）、LINEに貼ったときのカード（OGP）、
操作しやすさ（ラベル・押しやすさ・文字の拡大）を73項目で確認します。

## 実運用モード（スプレッドシートを予約台帳にする）

予約を Google スプレッドシートに集めます。**スプレッドシートがそのまま管理画面になり**、
スマホの Google スプレッドシートアプリから予約一覧を確認・編集できます。

構成はこうなります。

```
お客様のスマホ  ──予約──▶  Google Apps Script  ──▶  スプレッドシート（予約台帳）
                                    └──▶  店舗にメール通知
```

#### 手順

**1. スプレッドシートを作る**

Google ドライブで新しいスプレッドシートを作成します。名前は「予約台帳」など任意で構いません。

**2. スクリプトを貼る**

そのスプレッドシートで **拡張機能 → Apps Script** を開き、
最初から入っているコードをすべて消して、このリポジトリの
[`gas/Code.gs`](gas/Code.gs) の中身を貼り付けます。

先頭の設定を自分のものに変えてください。

```js
const NOTIFY_EMAIL = 'zer01.barber@gmail.com';  // 通知を受け取るメールアドレス
const CALENDAR_ID  = 'primary';                 // Googleカレンダーに入れる場合
```

**3. 「はじめの準備」を実行する**

貼り付けたコードの上のほうにある

```js
const PASSWORD = '';   // 例）'zer01-2026' のように決めてください
```

に、**管理ページで使いたいパスワード**を書きます。

そのうえで、エディタ上部の関数選択で **`はじめの準備`** を選んで実行してください。
初回は権限の確認画面が出るので許可してください
（「このアプリは確認されていません」と出たら、詳細 → 安全ではないページに移動）。

これ1回で次がまとめて終わります。

- 予約台帳・メニュー・クーポン・スタイル・休業日・設定 の6枚のシート作成
- 管理ページのパスワードの登録（スクリプトプロパティへ保存）
- 足りない設定と残りの手順を実行ログに表示

**終わったら `PASSWORD` の行は `''` に戻してください。**
保存済みなので消しても動きます。コードに残したままだと、画面を見せた相手に読まれます。

**4. 予約が届くか試す**

エディタ上部の関数選択で `testReserve` を選んで実行します。
初回は権限の確認画面が出るので許可してください
（「このアプリは確認されていません」と出たら、詳細 → 安全ではないページに移動）。

スプレッドシートに見出し行とテスト予約が1件入り、メールが届けば成功です。
確認できたらテスト行は削除して構いません。

**5. ウェブアプリとして公開する**

**デプロイ → 新しいデプロイ → 種類の選択で「ウェブアプリ」** を選び、

| 項目 | 設定 |
| --- | --- |
| 次のユーザーとして実行 | 自分 |
| アクセスできるユーザー | **全員** |

「アクセスできるユーザー」を**全員**にしないと、お客様からの予約が届きません。
ここはスプレッドシート自体が公開されるわけではなく、
受け口だけが公開される設定なので、台帳の中身は他人には見えません。

発行された `https://script.google.com/macros/s/.../exec` をコピーします。

**6. サイトにURLを貼る**

`assets/js/data.js` の `reservationEndpoint` に貼り付けて push すれば完了です。

```js
reservationEndpoint: 'https://script.google.com/macros/s/xxxxx/exec',
```

#### 届くもの

| タイミング | スプレッドシート | メール |
| --- | --- | --- |
| 予約が入ったとき | 1行追加（状態＝予約確定） | 店舗へ【新規予約】／お客様へ予約確認 |
| お客様がキャンセルしたとき | その行の状態を「キャンセル」に変更＋取り消し線 | 店舗へ【キャンセル】／お客様へ受付完了 |
| 予約画面を開いたとき | 変更なし（読み取りのみ） | — |

お客様への確認メールを止めたい場合は、`gas/Code.gs` の
`MAIL_TO_CUSTOMER` を `false` にしてください。

#### 前日リマインド（任意）

`sendReminders` という関数を用意しています。Apps Script の「トリガー」で
「時間主導型 → 日付ベースのタイマー（例：午後6時〜7時）」に設定すると、
翌日ご来店のお客様へリマインドメールが届きます。

台帳の列は 予約番号 / 受付日時 / 来店日 / 開始 / 終了 / 所要(分) / メニュー / 担当 /
担当ID / 指名料 / 合計金額 / お名前 / フリガナ / 電話番号 / メール / 来店回数 /
ご要望 / 状態 / カレンダーID です。

#### 補足

送信時の `Content-Type` を `text/plain` にしているのは意図的です。
`application/json` にするとブラウザが事前確認（OPTIONS リクエスト）を送りますが、
Apps Script はこれに応答できないため、送信が必ず失敗します。

## メニューをスプレッドシートで管理する

GAS を設置したあと、エディタで **`setupMenuSheets` を1回実行**してください。
スプレッドシートに「メニュー」「クーポン」の2枚が追加されます。

以降は、**この2枚の行を足す・消すだけでサイトのメニューが変わります。**
GitHub を触る必要はありません。

### メニューシート

| 区分 | メニュー名 | 価格 | 所要(分) | 説明 | 表示 |
| --- | --- | --- | --- | --- | --- |
| カット | メンズカット | 4000 | 50 | シャンプー込み | ○ |
| カラー | 白髪ぼかし | 9900 | 90 | | ○ |
| 期間限定 | 夏のクールスパ | 3000 | 30 | | × |

- **区分** が同じものは、メニューページで1つのグループにまとまります
- **所要(分)** は空席カレンダーの押さえ時間になります。実際の施術時間を入れてください
- **表示** を `×` にすると、行を消さずにサイトから隠せます（季節メニューの出し入れに便利）

### クーポンシート

| クーポン名 | 価格 | 通常価格 | 所要(分) | 説明 | 条件 | 対象 | 表示 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 初回カット | 4000 | 5000 | 50 | | 初めての方 | 新規 | ○ |

- **通常価格** を入れると、その金額に取り消し線が入ります。空欄なら表示されません
- **対象** は `新規` / `再来` / `全員` を想定しています

### 休業日シート

| 休業日 | メモ |
| --- | --- |
| 2026-09-15 | 東京出張 |
| 2026-09-16 | 東京出張 |

**日付を1行足すだけで、その日は予約できなくなります。**
出張や臨時休業はここで管理してください（コードを触る必要はありません）。
削除すればまた予約を受け付けます。

シートが空、または GAS 未設置の場合は `assets/js/data.js` の内容がそのまま使われます。

## Googleカレンダー連携

`gas/Code.gs` の `CALENDAR_ID` を設定すると、予約が入ったときに
Googleカレンダーへ自動で登録されます。キャンセル時には削除されます。

```js
const CALENDAR_ID = 'primary';   // 自分のメインカレンダーに入れる場合
```

予約用のカレンダーを分けたい場合は、Googleカレンダーで新しいカレンダーを作り、
設定画面の「カレンダーの統合」にあるカレンダーIDを貼ってください。

スマホの標準カレンダーに予約が並び、通知も鳴るようになります。
1人で運営される場合、これが実質的に一番使いやすい管理画面になります。

## LINE公式アカウントへの通知

`gas/Code.gs` の `LINE_TOKEN` と `LINE_TO` を設定すると、
予約とキャンセルがLINEに届きます。空のままなら何もしません。

- `LINE_TOKEN` … LINE Developers の Messaging API チャネルで発行する
  「チャネルアクセストークン（長期）」
- `LINE_TO` … 送信先のユーザーIDまたはグループID

メールは開かれにくいため、実運用ではLINEのほうが確実です。

### 写真の登録

次の場所で「写真を選ぶ」から、スマホのカメラロールの写真をそのまま登録できます。

| 場所 | 出るところ |
| --- | --- |
| 写真タブ | ギャラリー（ヘアカタログ・店内） |
| メニュー・クーポンの各行 | メニューページの一覧 |
| 店舗情報「ロゴ画像」 | ヘッダー・フッター・トップ |
| 店舗情報「スタッフ写真」 | スタッフ紹介 |
| 店舗情報「メイン写真」 | トップの一番上（大きく出ます） |

1. 選んだ写真は、送る前にブラウザ側で**長辺1200pxまで縮小**されます
   （スマホの写真はそのままだと数MBあり、Apps Script が受け取りきれないため）
2. Apps Script が Google ドライブの **「ZER01サイト画像」フォルダ**に保存します
3. ファイル名は `menus-0-20260815-143000.jpg` のように**自動で付け直します**
   （日本語ファイル名や重複でつまずかないようにするため）
4. 返ってきたURLが欄に入るので、**「保存」を押すとサイトに出ます**

保存された写真は「リンクを知っていれば誰でも閲覧できる」設定になります。
サイトに載せる写真のための設定なので、**それ以外の写真をこのフォルダに置かないでください。**

### ギャラリーの分類

写真タブの「分類」に入れた言葉が、そのままギャラリーの絞り込みタブになります。
`ショート` `フェード` `カラー` `パーマ` `店内` のように、店で使いたい言葉を入れてください。
同じ分類の写真はまとめて並びます。

### 定休曜日

店舗情報タブの「定休曜日」で曜日を選ぶと、**毎週その曜日がずっと予約できなくなります。**
「日曜は予定があるので閉める」といった固定の休みはこちらです。
1日だけ休むときは「休業日」タブを使ってください。

### パスワードの設定

**パスワードはサイトのソースに置きません。**
Apps Script の「プロジェクトの設定 → スクリプト プロパティ」で
`ADMIN_PASSWORD` という名前で登録してください。

入力された値は Apps Script 側で照合されるため、
サイトのソースを読まれてもパスワードは分かりません。

> 逆に言うと、**`ADMIN_PASSWORD` を登録するまで管理ページは使えません。**
> Google Apps Script を設置していない状態では、ログイン欄も無効になります。

### なぜ Apps Script を入れないと管理ページが開かないのか

理由は2つあり、どちらも避けられません。

1. **合言葉を照合する場所が要る。**
   このサイトは GitHub Pages に置いた HTML と JavaScript だけでできています。
   ソースは誰でも「ページのソースを表示」で読めるので、
   そこにパスワードを書くと**書いた時点で全員に見えます。**
   照合はサイトの外＝ Apps Script 側でやるしかありません。

2. **そもそも見せる中身が Apps Script 側にある。**
   予約一覧・休業日・メニュー・口コミは、すべてスプレッドシートの中です。
   Apps Script が無い状態では、管理ページが読みに行く先自体がありません。

裏を返すと、**Apps Script を1回入れれば、予約の受付と管理ページが同時に動き出します。**
別々の作業ではありません。手順は上の「Apps Script の設置」を見てください。

### 端末を記憶する

ログイン画面の「この端末を記憶する」を選ぶと、次からパスワードなしで開けます。

端末に残るのは**パスワードそのものではなく、その端末用の合鍵**です。
合鍵は Apps Script 側で発行し、60日で切れます。

- **1台だけ解除したい** → その端末で「この端末の記憶を消す」を押す
- **全部まとめて解除したい**（端末を紛失したときなど）
  → Apps Script のエディタで `revokeAllAdminTokens` を実行する

店舗の端末以外で開くときは、チェックを外してお使いください。

## 設定を書き間違えたとき

営業時間は「09:00」の形でないと予約枠を1つも作れず、
**カレンダーが黙って空になります**。シートは手で書く場所なので、
「9時」のような書き方も読み取れるようにしてあります。

それでも読めない値、開始と終了が逆になっている値は**無視して、
`data.js` の営業時間を使います**（ブラウザのコンソールに理由が出ます）。
最終受付が営業終了より後の場合は、営業終了に合わせます。

価格・所要時間の欄に数字以外が入っていた場合も、
取り込み時に数値へそろえます（所要時間は予約枠の長さに戻します）。

## 2人で同時に管理ページを使うとき

管理ページは**シートをまるごと書き換えます**。
そのため、2人が同時に開いて別々に保存すると、
あとから保存した側が相手の変更を消してしまいます。

読み込んだ時点のシートの中身から短い印を作り、保存時に照合しています。
そのあいだに別の端末から保存されていた場合は**保存せずに知らせ、
その場に「読み込み直す」ボタンを出します**。

## 送信できなかったとき

予約・変更・キャンセルは、Apps Script が **`{ ok: true }` を返したときだけ成功**として扱います。

通信そのものに失敗した場合は、1度だけ自動でやり直します
（Apps Script は久しぶりの呼び出しで立ち上がりに時間がかかることがあるため）。
それでも届かなかった場合は、次のようにします。

| 操作 | 届かなかったとき |
| --- | --- |
| 予約 | 完了画面に赤い枠で警告を出し、予約番号を控えて連絡するようご案内します |
| 日時変更 | **日時を書き換えずに**やり直しをご案内します |
| キャンセル | 同上 |

日時変更でとくに注意が必要なのは、画面だけ書き換えると
**お客様が変更できたつもりで元の時間に来てしまう**ことです。
届かなかったときは変更しません。

## 口コミ

**ご来店いただいた方だけ**が投稿でき、**店舗が承認したものだけ**が掲載されます。

### お客様側

口コミページ下部のフォームから、**ご予約番号とお電話番号**を添えて投稿します。
予約確認ページの過去のご予約にも「ご感想を書く」ボタンが出ます。

Apps Script 側で次を確認しています。

- 予約番号と電話番号が一致すること（実際に来店した方であること）
- **来店日を過ぎていること**（来店前には書けません）
- キャンセルされた予約でないこと
- 同じ予約からの二重投稿でないこと

### 店舗側

管理ページの「口コミ」タブに届きます。届いた直後は **「未承認」** で、
**「掲載中」にするまでサイトには出ません。**

| 状態 | 意味 |
| --- | --- |
| 未承認 | 届いたまま。サイトには出ません |
| 掲載中 | サイトに出ます |
| 非掲載 | 出しません（記録は残ります） |

**本文・評価・お名前は書き換えられないようにしてあります。**
店舗が触れるのは「掲載するかどうか」と削除だけです。
お客様の言葉を変えて載せると、景品表示法（ステルスマーケティング規制）に
触れるおそれがあるためです。

### 評価の数値について

トップと口コミページの★は、**掲載中の口コミから計算**しています。
1件も掲載していないあいだは、評価の表示自体が出ません。

> 掲載元サイト（ホットペッパービューティー）の評価は、この店の実績ではあっても
> **このサイトに寄せられた評価ではない**ため、転記していません。

## ご予約の日時変更

予約確認ページの「日時を変更する」から、**キャンセルせずに日時だけ**変更できます。

- **予約番号は変わりません**
- メニュー・ご担当・お客様情報はそのまま
- 元の枠はその場で空き、新しい枠が埋まります
- 別の端末からでも、予約番号＋電話番号で照会すれば変更できます

キャンセルして取り直す方式だと、そのあいだに枠を他のお客様に取られます。
この方式なら、新しい枠が確保できたときだけ元の枠が空きます。

変更後は、お客様と店舗の両方にメール（＋LINE設定時はLINE）が届き、
Googleカレンダーの予定も入れ直されます。

> 送信の直前にもう一度空き状況を取り直し、Apps Script 側でも
> 同じ担当・同じ時間に別の予約が無いかを確認しています。
> 画面を開いたまま放置しているあいだに埋まった場合は、日時選択に戻ります。

受付期限はキャンセルと同じ**前日18時まで**です。

## 変更・キャンセルの受付期限

初期値は**前日18時**です。変えるときは**2か所**を同じ値にしてください。

| 場所 | 項目 |
| --- | --- |
| `assets/js/data.js` | `business.cancelDeadline`（`{ daysBefore: 1, hour: 18 }`） |
| `gas/Code.gs` | `CANCEL_DEADLINE_DAYS_BEFORE` / `CANCEL_DEADLINE_HOUR` |

Apps Script から `data.js` は読めないため、同じ値を2か所に置いています。

判定は**画面と Apps Script の両方**で行います。
画面だけだと、期限の直前にページを開いたまましばらくして押された場合に
すり抜けます（17時58分に開いて18時03分に押す、前夜に開いたまま翌朝押す、など）。
すり抜けた分は Apps Script が断り、その理由を画面に出します。

すでにキャンセル済みの予約をもう一度キャンセルしても、
**通知やメールは二重に飛びません**。

## 地図・道案内

サロン情報の下に「地図で見る」「ここへの経路を調べる」のボタンが出ます。
Googleマップが開き、**現在地からの道順**がそのまま表示されます。

検索に使う文字列は `data.js` の `mapQuery` です。
部屋番号（002）まで入れるとGoogleマップが見つけられないことがあるため、
建物名までにしてあります。地図でうまく出ない場合はここを調整してください。

> Googleマップの埋め込み（iframe）は使っていません。
> 第三者のスクリプトを読み込むことになるうえ、開発環境から表示確認ができないためです。
> リンクなら確実に開きます。

## カレンダーへの登録

予約完了画面に「カレンダーに追加」ボタンが出ます。
押すと `.ics` ファイルが保存され、iPhone・Android・PCのどのカレンダーでも開けます。

- 来店の**2時間前に通知**が鳴るよう設定してあります
- 予約番号・メニュー・担当・合計金額・予約確認ページのURLが説明欄に入ります

LINEの前日リマインドが使えるようになるまで、無断キャンセル対策はこれが主役になります。

## ご予約の確認（ログインなし）

`mypage.html` では、**ご予約番号とお電話番号**でご予約を照会できます。
両方が一致した場合のみ内容を返すため、他人のご予約は見られません。

アカウント登録なしで、機種変更後や別のブラウザからでも確認・キャンセルができます。
（この端末で取ったご予約は、入力しなくても一覧に表示されます）

## 空席状況について

初期状態の空席カレンダーはサンプルです。次のルールで組み立てています。

- 定休日・臨時休業日・過去の時間・受付締切（`minLeadHours`）を除外
- スタッフの出勤曜日（`workdays`）を反映
- 1日に1〜3件の先約が入っている想定でブロックを生成
- 選択中メニューの合計所要時間ぶん、連続して空いている枠だけを予約可に
- この端末から入れた予約は、その担当の枠を実際に埋める

実際の予約管理システムとつなぐときは、`assets/js/common.js` の
`Availability.isStaffSlotFree()` を自社の空き状況を返す処理に置き換えてください。
ここ1箇所の変更で全画面に反映されます。

### ダブルブッキングの防止

受信先（GAS）を設定していると、予約画面を開いたときに
**他のお客様の予約済み枠を取得して空席カレンダーに反映**します。
別の端末から入った予約もその場で × になります。

さらに、確認画面で「この内容で予約する」を押した瞬間にもう一度最新の状況を取り直し、
その間に同じ枠が埋まっていた場合は予約を中止して日時選択に戻します。

受け取るのは「日付・開始時刻・所要時間・担当ID」だけで、
**氏名や電話番号などの個人情報は一切返しません。**
受信先は「全員がアクセスできる」設定で公開するため、ここは重要な点です。

受信先が未設定、または通信に失敗した場合は、その端末の予約だけで判定して動作を続けます。

## 管理画面について

`admin.html` から、そのブラウザに入っている予約の一覧・絞り込み・CSV出力・
キャンセルができます。入口のパスコードは `data.js` の `adminPasscode` です。

ただし**日常の予約確認は、GAS で連携したスプレッドシートを見るのが確実です。**
`admin.html` はそのブラウザに保存された予約しか表示できないため、
お客様の端末から入った予約は表示されません。

> **注意:** パスコードはソースを読めば分かります。
> 本番で顧客情報を扱う場合は、必ずサーバー側の認証を用意してください。
